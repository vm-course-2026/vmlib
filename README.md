# vmlib

`vmlib` — компактная библиотека для воспроизводимых экспериментов с
численными методами. Она измеряет время и вычислительную стоимость, считает
ошибки и эмпирические порядки сходимости, сравнивает результаты, строит
таблицы, диагностические графики и анимации. Сами численные алгоритмы в
библиотеку не входят.

Имя дистрибутива — **`vmlib-course`**, импорт — **`import vmlib as vm`**.
Поддерживаются Python 3.11–3.13. В заданиях курса используется Python 3.12.

## Если вы студент и получили домашнюю работу

Клонируйте **свой репозиторий задания**, откройте его папку и выполните:

```bash
uv sync --locked
uv run --locked vmlib-doctor
```

Отдельно клонировать этот репозиторий, копировать папку `vmlib` или настраивать
submodule не нужно. Библиотека автоматически устанавливается в `.venv`
задания из публичного репозитория; членство в организации библиотеки не нужно.
Команда `pip install vmlib` **не является способом установки этой библиотеки**.

В VS Code установите расширения Microsoft **Python** и **Jupyter**. В правом
верхнем углу ноутбука выберите kernel из `.venv` именно этой работы, затем
выполните **Restart Kernel → Run All**. Выбор Python Interpreter для `.py`
сам по себе не гарантирует смену kernel ноутбука.

`vmlib-doctor` печатает версии и fingerprint; это проверка импорта и среды,
а не подтверждение правильности вашего численного метода. Проверки самой
домашней работы и команда сдачи описаны в её README.

## Пример: результат, ошибка и вычислительная стоимость

Сохраните код в `example.py` и запустите `uv run --locked python example.py`:

```python
import numpy as np
import vmlib as vm

reference = np.array([1.0, 0.5, 0.25])
approximation = reference + np.array([1e-5, -2e-5, 1e-5])

with vm.timed() as timer:
    error = vm.max_error(approximation, reference)

result = vm.Result(
    x=approximation,
    success=bool(np.isfinite(error)),
    elapsed_time=timer.elapsed,
    max_error=error,
)
assert vm.compare(result.x, reference, tol=3e-5, verbose=False)
print(result)

counted = vm.CallCounter(np.sin)
timing = vm.benchmark(counted, np.linspace(0, 1, 1000), repeats=3, reset=counted)
assert counted.count == 1  # один векторный вызов в последнем прогоне, не 1000
print(timing)
```

`Result` хранит переданные метрики, но не вычисляет их и не проверяет метод
за вас. `max_error` — абсолютная максимальная ошибка при совпадающих формах.
`timed` измеряет один участок, `benchmark` — повторы с прогревом; `reset`
не даёт суммировать счётчик между прогонами. Малые времена зависят от машины.

## Пример: проверка порядка и сохранение графика

Этот самостоятельный пример не требует окна графики и создаёт `convergence.png`:

```python
import matplotlib
matplotlib.use("Agg")  # выбрать до импорта pyplot и vmlib
import matplotlib.pyplot as plt
import numpy as np
import vmlib as vm

hs = np.array([0.4, 0.2, 0.1, 0.05, 0.025])
# Центральная разность для sin'(0) = 1; метод здесь реализован пользователем.
approximations = (np.sin(hs) - np.sin(-hs)) / (2 * hs)
errors = np.abs(approximations - 1.0)
table = vm.convergence(hs, errors, expected=2)
assert np.all((table.orders > 1.9) & (table.orders < 2.1))
print(table.verdict())
ax = vm.convergence_plot(
    {"Центральная разность": (hs, errors)},
    expected_orders={"Центральная разность": 2},
    save="convergence.png",
)
plt.close(ax.figure)
```

## Что есть в библиотеке

| Задача | API |
|---|---|
| Метрики результата | `Result` |
| Время и число вызовов | `timed`, `benchmark`, `CallCounter` |
| Ошибки и порядок | `max_error`, `l2_error`, `rel_error`, `convergence` |
| Таблицы и графики | `compare_methods`, `convergence_plot`, `cost_vs_error`, `residual_history` |
| Самопроверки | `compare`, `check_order`, `check_invariant`, `report` |
| GIF и раскадровки | `Scene`, `Meter`, `render`, `render_frames` |

Для анимации наследник `Scene` реализует `setup(ax)` и `draw(ax, k, t)`.
Координаты и численный алгоритм задаёт ваш код; `render` отвечает за отрисовку
и GIF через Pillow — ffmpeg не нужен. Повторная отрисовка одного кадра не
должна продвигать расчёт: удобно заранее вычислить траекторию и индексировать её.

Сигнатуры и ограничения описаны в docstring модулей, примеры граничных
случаев — в [`tests/test_vmlib.py`](tests/test_vmlib.py). Подробности запуска
и отладки — в [`ЗАПУСК.md`](ЗАПУСК.md).

## Инварианты качества

- `NaN` и `Inf` не должны превращаться в успешную проверку; диагностические
  графики могут исключать непригодные точки с предупреждением;
- формы массивов должны совпадать, broadcasting в метриках запрещён;
- порядок оценивается минимум по четырём сеткам;
- точки на уровне численного шума исключаются с явной диагностикой;
- график «ошибка — стоимость» не смешивает разные единицы;
- вычислительное время и время отрисовки анимации учитываются отдельно.

Версия доступна как `vmlib.__version__`, а
`vmlib.source_fingerprint()` помогает отличить разные копии исходников.
В версии 1.1.0 он чувствителен к переводам строк LF/CRLF: на разных ОС один
Git-релиз может иметь разные отпечатки. Это диагностика, не идентификатор
релиза и не цифровая подпись; не блокируйте запуск только из-за этого различия.
Справочник публичных функций находится в docstring соответствующих модулей.

## Версии в домашних работах

Для новых домашних работ используем **версионный тег + lockfile**:

```toml
[project]
dependencies = ["vmlib-course==1.1.0"]

[tool.uv.sources]
vmlib-course = { git = "https://github.com/vm-course-2026/vmlib", tag = "v1.1.0" }
```
Студент клонирует только свой репозиторий:
`uv sync --locked` сам устанавливает именно проверенный релиз. Изменение
`main`, новый тег или новый релиз `vmlib` не меняют уже выданную работу.

Опубликованные теги не перемещаются и не заменяются. Исправление выпускается
новой patch-версией, например `1.1.0` → `1.1.1`:

- если дефект не влияет на условие, результат или проверку текущей работы,
  новый релиз используется только в будущих ДЗ;
- если влияет, преподаватели сначала добавляют регрессионный тест, выпускают
  patch-релиз и проверяют эталонную работу; сначала обновляют template через
  PR, затем открывают в каждом уже выданном личном репозитории адресный PR;
- такой PR атомарно меняет ровно `pyproject.toml`, `uv.lock` и vmlib-секцию
  `.vm-course/assignment.json`; версия условия ДЗ при библиотечном patch
  остаётся прежней. После слияния студент сохраняет/коммитит свою работу,
  выполняет `git pull --ff-only`, затем `uv sync --locked` и перезапускает
  Jupyter kernel. При конфликте не нужно делать force-push или reset;
- старые коммиты остаются воспроизводимыми и проверяются по старому release
  contract. Обновление не должно задним числом ухудшать оценку или сокращать
  срок сдачи.

Самостоятельно запускать `uv lock`, подменять источник или переходить на
«последнюю» `vmlib` в домашней работе не нужно: официальный update-PR содержит
весь согласованный набор файлов.

`--locked` сообщает о рассогласовании lockfile с `pyproject.toml`, не изменяя
его. Старые инструкции с `--frozen` тоже используют сохранённый lockfile,
но **пропускают проверку его актуальности**. Для нового задания используем
`--locked`; ошибку согласованности должен исправить преподаватель, а не студент
случайным обновлением всех зависимостей.
