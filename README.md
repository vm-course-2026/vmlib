# vmlib

`vmlib` — компактная библиотека для воспроизводимых экспериментов с
численными методами. Она измеряет время и вычислительную стоимость, считает
ошибки и эмпирические порядки сходимости, сравнивает результаты, строит
таблицы, диагностические графики и анимации. Сами численные алгоритмы в
библиотеку не входят.

Имя дистрибутива при установке — **`vmlib-course`**, имя пакета в Python —
**`vmlib`**:

```bash
uv add "vmlib-course @ git+https://github.com/vm-course-2026/vmlib.git@v1.1.0"
uv run vmlib-doctor
```

```python
import numpy as np
import vmlib as vm

reference = np.array([1.0, 0.5, 0.25])
approximation = reference + np.array([1e-5, -2e-5, 1e-5])

with vm.timed() as timer:
    error = vm.max_error(approximation, reference)

result = vm.Result(
    x=approximation,
    success=np.isfinite(error),
    elapsed_time=timer.elapsed,
    max_error=error,
)
assert vm.compare(result.x, reference, tol=3e-5, verbose=False)
```

Подробные варианты установки, настройка VS Code, локальная разработка и
диагностика описаны в [`ЗАПУСК.md`](ЗАПУСК.md).

## Разработка

```bash
git clone https://github.com/vm-course-2026/vmlib.git
cd vmlib
uv sync --frozen --extra test
uv run pytest
uv run python tools/build_release.py
```

Поддерживаются Python 3.11–3.13. Все 35 регрессионных тестов должны пройти.
Импорт `vmlib` не меняет выбранный backend Matplotlib; для среды без дисплея
задайте `MPLBACKEND=Agg` при запуске процесса.

Релизный скрипт выполняет две независимые сборки и требует совпадения их
SHA-256. В sdist он фиксирует время и нормализует владельца каждого tar-файла
как `0:0 root:root`, поэтому архив не раскрывает локальное имя пользователя.
Команда `uv run python tools/build_release.py --check-only` повторно проверяет
уже созданные артефакты без пересборки.

## Инварианты качества

- `NaN` и `Inf` не фильтруются молча;
- формы массивов должны совпадать, broadcasting в метриках запрещён;
- порядок оценивается минимум по четырём сеткам;
- точки на уровне численного шума исключаются с явной диагностикой;
- график «ошибка — стоимость» не смешивает разные единицы;
- вычислительное время и время отрисовки анимации учитываются отдельно;
- HTML из названий и результатов экранируется.

Версия доступна как `vmlib.__version__`, а
`vmlib.source_fingerprint()` помогает отличить разные копии исходников.
Справочник публичных функций находится в docstring соответствующих модулей.

## Версии в домашних работах

Домашняя работа закрепляет одновременно номер версии, полный 40-символьный
commit `vmlib` и `uv.lock`. Поэтому студент клонирует только свой репозиторий:
`uv sync --frozen` сам устанавливает именно проверенный релиз. Изменение
`main`, новый тег или новый релиз `vmlib` не меняют уже выданную работу.

Опубликованные теги не перемещаются и не заменяются. Исправление выпускается
новой patch-версией, например `1.1.0` → `1.1.1`:

- если дефект не влияет на условие, результат или проверку текущей работы,
  новый релиз используется только в будущих ДЗ;
- если влияет, преподаватели сначала добавляют регрессионный тест, выпускают
  patch-релиз и проверяют эталонную работу, затем открывают в каждом личном
  репозитории одинаковый PR;
- такой PR атомарно меняет версию самой ДЗ, её release manifest,
  `pyproject.toml` и `uv.lock`; после слияния достаточно снова выполнить
  `uv sync --frozen`;
- старые commit остаются воспроизводимыми и проверяются по старому release
  contract. Обновление не должно задним числом ухудшать оценку или сокращать
  срок сдачи.

Самостоятельно запускать `uv lock`, подменять источник или переходить на
«последнюю» `vmlib` в домашней работе не нужно: официальный update-PR содержит
весь согласованный набор файлов.
