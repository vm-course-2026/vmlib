# Как участвовать в разработке

## Issue

Сначала найдите существующий issue. Если совпадения нет, создайте отчёт по
шаблону и укажите:

1. минимальный воспроизводимый пример;
2. ожидаемое и фактическое поведение;
3. полный traceback;
4. ОС, версию Python, `vmlib.__version__` и
   `vmlib.source_fingerprint()`;
5. воспроизводится ли дефект после чистой установки.

Не публикуйте токены, персональные данные, закрытые исходники и большие
бинарные артефакты. Потенциальные уязвимости отправляйте только по процедуре из
[`SECURITY.md`](SECURITY.md).

Метка `needs-triage` означает, что отчёт ещё не разобран, а
`needs-reproduction` — что сопровождающим не хватает воспроизводимого примера.

## Pull request

Создайте отдельную ветку от актуальной `main`. Одно изменение должно решать
одну проблему и ссылаться на issue. Изменение поведения сопровождается
регрессионным тестом; несовместимое изменение публичного API сначала
обсуждается в issue.

```bash
uv sync --frozen --extra test
uv run pytest
uv build --clear --no-create-gitignore
```

Для изменения графиков или анимаций приложите компактное сравнение до/после,
но не добавляйте большие бинарные файлы в git. Перед отправкой заполните весь
PR checklist. Слияние разрешается только после стабильного check
`quality-gate`.
