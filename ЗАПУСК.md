# Установка, запуск и разработка vmlib

Эта инструкция относится к самостоятельному репозиторию `vmlib`. Имя
дистрибутива — `vmlib-course`, а импортируемого Python-пакета — `vmlib`.
Поддерживаются Python 3.11, 3.12 и 3.13.

## 1. Установить инструменты

Для использования достаточно Git и `uv`. Редактор VS Code необязателен.

- macOS: установите Command Line Tools командой `xcode-select --install`,
  затем `brew install uv`;
- Windows: выполните `winget install Git.Git` и
  `winget install --id astral-sh.uv` в PowerShell;
- Linux: установите Git из пакетного менеджера, затем `uv` по
  [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/).

После установки откройте новый терминал и проверьте:

```bash
git --version
uv --version
```

Отдельная системная установка Python не обязательна: `uv` умеет установить
поддерживаемую версию в изолированное окружение.

## 2. Подключить vmlib к своему проекту

В существующем проекте под управлением `uv` выполните:

```bash
uv add "vmlib-course @ git+https://github.com/vm-course-2026/vmlib.git@v1.1.0"
```

Тег фиксирует конкретную версию и делает окружение воспроизводимым. Для
обновления замените тег на опубликованную версию и снова выполните `uv lock`.

Если собственного `pyproject.toml` пока нет:

```bash
mkdir vmlib-example
cd vmlib-example
uv init
uv add "vmlib-course @ git+https://github.com/vm-course-2026/vmlib.git@v1.1.0"
```

Проверьте установку:

```bash
uv run vmlib-doctor
uv run python -c "import vmlib; print(vmlib.__version__, vmlib.source_fingerprint())"
```

В Python библиотека всегда импортируется так:

```python
import vmlib as vm
```

## 3. Открыть проект в VS Code

Откройте корень своего проекта:

```bash
code .
```

Установите расширение **Python** от Microsoft. Затем выберите команду
**Python: Select Interpreter** и интерпретатор `.venv/bin/python` на
macOS/Linux или `.venv\Scripts\python.exe` на Windows. Терминал и редактор
должны использовать одно и то же окружение.

## 4. Подготовить копию для разработки

```bash
git clone https://github.com/vm-course-2026/vmlib.git
cd vmlib
uv sync --frozen --extra test
uv run vmlib-doctor
uv run pytest
```

`--frozen` запрещает незаметно менять `uv.lock`. Если вы намеренно изменили
зависимости в `pyproject.toml`, выполните `uv lock`, проверьте diff lock-файла,
а затем повторите тесты.

Полезные варианты запуска:

```bash
uv run pytest -q
uv run pytest -k convergence -vv
uv run pytest -x --pdb
```

Для отладки `.py` поставьте breakpoint слева от номера строки и выберите
**Run and Debug → Python File**. Убедитесь, что выбран интерпретатор из
`.venv`; иначе редактор и команды `uv run` могут видеть разные установки.

## 5. Проверить дистрибутив перед выпуском

```bash
uv build --clear --no-create-gitignore
```

Команда сначала удаляет прежнее содержимое `dist/`, затем создаёт один wheel и
один sdist. Устанавливать для проверки нужно именно wheel, а не рабочее дерево:

```bash
uv venv --clear .wheel-smoke
uv pip install --python .wheel-smoke/bin/python dist/vmlib_course-1.1.0-py3-none-any.whl
.wheel-smoke/bin/python -c "import vmlib; print(vmlib.__version__)"
```

В Windows две последние команды выглядят так:

```powershell
uv pip install --python .wheel-smoke\Scripts\python.exe dist\vmlib_course-1.1.0-py3-none-any.whl
.wheel-smoke\Scripts\python.exe -c "import vmlib; print(vmlib.__version__)"
```

## 6. Графика в среде без дисплея

`vmlib` не переключает backend Matplotlib при импорте. Для CI или удалённого
процесса задайте backend снаружи:

```bash
MPLBACKEND=Agg uv run pytest
```

В PowerShell:

```powershell
$env:MPLBACKEND = "Agg"
uv run pytest
```

## 7. Частые проблемы

| Симптом | Что проверить |
|---|---|
| `uv: command not found` | Откройте новый терминал и повторите `uv --version`. |
| `ModuleNotFoundError: vmlib` | Запускайте через `uv run`; проверьте, что зависимость есть в `pyproject.toml`. |
| VS Code не видит пакет | Выберите интерпретатор из `.venv` и перезапустите Python-процесс. |
| Тесты видят старый код | Проверьте `uv run python -c "import vmlib; print(vmlib.__file__)"`. |
| Окно графика недоступно | Запустите процесс с `MPLBACKEND=Agg` и сохраняйте рисунок в файл. |
| `uv sync --frozen` сообщает об устаревшем lock-файле | Для разработки обновите `uv.lock`; для обычной установки восстановите файлы репозитория. |

Если ошибка остаётся, запустите `uv run vmlib-doctor` и приложите его вывод к
issue вместе с точной командой и traceback. Перед публикацией удалите токены,
персональные данные и закрытые фрагменты исходников.
